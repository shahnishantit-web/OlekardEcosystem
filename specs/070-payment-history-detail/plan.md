# Implementation Plan: P23 — Payment History, Detail and Transaction Management

**Branch**: `070-payment-history-detail` | **Date**: 2026-10-26 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/070-payment-history-detail/spec.md`

---

## Summary

Upgrade the existing `transactions/` modules in both Flutter apps (customer + agent) to consume the P19 payment history API. Delivers: filterable paginated activity feed, rich status detail with 4 discrete status rows, scoped receipt access with single-use expiring download tokens, domain deep-link rendering, refund request routing via E62 eligibility, support-from-transaction pre-fill via E22, encrypted offline cache (`flutter_secure_storage`) with full logout eviction, and full accessibility compliance (44dp targets, 2× font scale, screen reader semantics).

---

## Technical Context

**Language/Version**: Dart 3.3+ / Flutter 3.19+

**Primary Dependencies**:
- `flutter_riverpod: ^3.1.0`, `riverpod_annotation: ^4.0.0` — state management (existing)
- `dio: ^5.4.3` — HTTP client (existing)
- `go_router: ^18.1.0` — navigation + deep links (existing)
- `flutter_secure_storage: ^11.2.0` — encrypted offline cache (existing in both app pubspecs)
- `flutter_windowmanager: ^0.2.0` — receipt screen screenshot guard (**NEW** — must add to both app pubspecs)
- `flutter_test`, `mockito` — testing

**Storage**:
- Online: P19 REST API (`GET /v1/payment/history`, `GET /v1/payment/receipts/{id}`, `POST /v1/payment/receipts/{id}/download-token`)
- Offline: `flutter_secure_storage` (AES-256 at rest) — stale-read cache; full eviction on logout

**Testing**: `flutter_test` (unit + widget), `mockito`, `integration_test`

**Target Platform**: iOS 14+ / Android 6.0+ (customer and agent apps)

**Project Type**: Mobile app feature upgrade — two existing apps; no new shared package

**Performance Goals**: History list first page ≤ 800 ms p95; receipt token fetch ≤ 600 ms p95; offline stale cache read ≤ 50 ms

**Constraints**:
- `refund_eligible` is server-authoritative — never locally overridden
- Receipt download token is single-use; must not be stored or logged
- `providerReference` masked in all display (last 4 chars + asterisks) — never logged
- Encrypted cache must evict fully on logout/account-switch
- Screenshot protection (`FLAG_SECURE` / iOS) on ReceiptScreen

**Scale/Scope**: ~5 screens upgraded per app; ~40 Dart files; 2 apps (customer + agent)
