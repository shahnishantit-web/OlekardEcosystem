# Data Model — E06 Wallet Management

All tables reside in the `wallet` PostgreSQL schema (DB connection: `wallet`).
Amounts are stored as **bigint integer minor units** (e.g., BWP thebe = 1/100 BWP).
All timestamps are `timestamptz` (UTC).
All IDs are UUID v7 (`varchar(36)` — Ramsey UUID v7).

---

## Entity Relationships

```
identity.users (E01)
  └── wallet.wallets  [owner_id FK]
        ├── wallet.wallet_status_history  [wallet_id FK]
        ├── wallet.wallet_limits          [wallet_id FK]
        └── wallet.currency_pockets       [wallet_id FK]
              └── wallet.wallet_holds     [pocket_id FK]

wallet.currencies  (configuration; no FK to wallets — read-only reference)
```

## Table: wallet.wallets

```sql
CREATE TABLE wallet.wallets (
    id               UUID        PRIMARY KEY,          -- UUID v7
    wallet_reference VARCHAR(32) NOT NULL UNIQUE,
    owner_id         UUID        NOT NULL,
    status           VARCHAR(20) NOT NULL DEFAULT 'pending',
    idempotency_key  VARCHAR(255),
    version          INTEGER     NOT NULL DEFAULT 0,
    created_by       UUID        NOT NULL,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT now(),

    CONSTRAINT wallets_status_check CHECK (
        status IN ('pending','active','frozen','suspended','restricted','closed')
    )
);

-- Prevent duplicate active wallets per user
CREATE UNIQUE INDEX wallets_owner_id_active_unique
    ON wallet.wallets (owner_id)
    WHERE status <> 'closed';

-- Idempotency replay
CREATE UNIQUE INDEX wallets_idempotency_key_unique
    ON wallet.wallets (idempotency_key)
    WHERE idempotency_key IS NOT NULL;

-- Cross-schema FK: owner_id references identity.users.id
ALTER TABLE wallet.wallets
    ADD CONSTRAINT wallets_owner_id_fk
    FOREIGN KEY (owner_id) REFERENCES identity.users(id);
```

### Field Notes

| Field | Notes |
|---|---|
| `id` | UUID v7; assigned at creation |
| `wallet_reference` | Format TBD-E06-007; generated by `WalletReferenceGenerator`; globally unique |
| `owner_id` | Immutable after creation; references `identity.users(id)` |
| `status` | Lifecycle state; enforced by `WalletStateMachine` |
| `idempotency_key` | Creation idempotency key from `Idempotency-Key` request header |
| `version` | Optimistic lock; incremented on every status change |
| `created_by` | Actor UUID; may be a system service actor for event-driven creation |

## Table: wallet.currency_pockets

```sql
CREATE TABLE wallet.currency_pockets (
    id                      UUID        PRIMARY KEY,      -- UUID v7
    wallet_id               UUID        NOT NULL,
    currency_code           VARCHAR(10) NOT NULL,
    ledger_account_reference VARCHAR(255) NOT NULL UNIQUE,
    status                  VARCHAR(20) NOT NULL DEFAULT 'active',
    created_by              UUID        NOT NULL,
    created_at              TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at              TIMESTAMPTZ NOT NULL DEFAULT now(),

    CONSTRAINT currency_pockets_status_check CHECK (
        status IN ('active','disabled')
    ),
    CONSTRAINT currency_pockets_wallet_currency_unique
        UNIQUE (wallet_id, currency_code)
);

ALTER TABLE wallet.currency_pockets
    ADD CONSTRAINT currency_pockets_wallet_id_fk
    FOREIGN KEY (wallet_id) REFERENCES wallet.wallets(id);

-- SELECT FOR UPDATE target — also used for balance queries
CREATE INDEX currency_pockets_wallet_id_idx
    ON wallet.currency_pockets (wallet_id);

CREATE INDEX currency_pockets_currency_code_idx
    ON wallet.currency_pockets (currency_code);
```

### Field Notes

| Field | Notes |
|---|---|
| `ledger_account_reference` | Opaque reference assigned by E07 at pocket creation; never mutated |
| `status` | `active` or `disabled`; disabled pockets cannot participate in transactions |
| No balance fields | Balance is derived at query time from E07 + `wallet_holds`; never stored directly |

## Table: wallet.wallet_holds

```sql
CREATE TABLE wallet.wallet_holds (
    id                    UUID        PRIMARY KEY,     -- UUID v7
    pocket_id             UUID        NOT NULL,
    amount                BIGINT      NOT NULL CHECK (amount > 0),
    currency_code         VARCHAR(10) NOT NULL,
    status                VARCHAR(20) NOT NULL DEFAULT 'active',
    transaction_reference VARCHAR(255),
    description           TEXT,
    expires_at            TIMESTAMPTZ,
    expired_at            TIMESTAMPTZ,
    released_at           TIMESTAMPTZ,
    created_by            UUID        NOT NULL,
    created_at            TIMESTAMPTZ NOT NULL DEFAULT now(),

    CONSTRAINT wallet_holds_status_check CHECK (
        status IN ('active','released','expired')
    )
);

ALTER TABLE wallet.wallet_holds
    ADD CONSTRAINT wallet_holds_pocket_id_fk
    FOREIGN KEY (pocket_id) REFERENCES wallet.currency_pockets(id);

-- Sum of active holds per pocket (held_amount computation)
CREATE INDEX wallet_holds_pocket_id_active_idx
    ON wallet.wallet_holds (pocket_id, status)
    WHERE status = 'active';

-- Expiry job: find expired holds
CREATE INDEX wallet_holds_expires_at_active_idx
    ON wallet.wallet_holds (expires_at, status)
    WHERE status = 'active' AND expires_at IS NOT NULL;
```

### Field Notes

| Field | Notes |
|---|---|
| `amount` | Integer minor units; always positive |
| `transaction_reference` | Opaque reference to the initiating transaction (E08/E09) |
| `expires_at` | Optional UTC expiry; processed by `wallet:expire-holds` job |
| `expired_at` | Set when `wallet:expire-holds` transitions status → `expired` |
| `released_at` | Set when transaction settlement/cancellation releases the hold |

## Table: wallet.wallet_limits

```sql
CREATE TABLE wallet.wallet_limits (
    id             UUID        PRIMARY KEY,     -- UUID v7
    wallet_id      UUID        NOT NULL,
    currency_code  VARCHAR(10) NOT NULL,
    limit_type     VARCHAR(50) NOT NULL,
    limit_value    BIGINT,                       -- NULL = unlimited
    is_tbd         BOOLEAN     NOT NULL DEFAULT false,
    effective_from TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by     UUID        NOT NULL,
    updated_by     UUID        NOT NULL,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now(),

    CONSTRAINT wallet_limits_type_check CHECK (
        limit_type IN (
            'daily_transaction_amount',
            'weekly_transaction_amount',
            'monthly_transaction_amount',
            'single_transaction_amount',
            'max_balance'
        )
    ),
    CONSTRAINT wallet_limits_unique
        UNIQUE (wallet_id, currency_code, limit_type)
);

ALTER TABLE wallet.wallet_limits
    ADD CONSTRAINT wallet_limits_wallet_id_fk
    FOREIGN KEY (wallet_id) REFERENCES wallet.wallets(id);
```

### Field Notes

| Field | Notes |
|---|---|
| `limit_value` | NULL means no limit enforced; seed values TBD-E06-004 via `is_tbd = true` |
| `is_tbd` | When `true`, enforcement logic logs a warning and skips enforcement |
| Uniqueness | One row per `(wallet_id, currency_code, limit_type)` |

## Table: wallet.wallet_status_history

```sql
CREATE TABLE wallet.wallet_status_history (
    id             UUID        PRIMARY KEY,     -- UUID v7
    wallet_id      UUID        NOT NULL,
    from_status    VARCHAR(20),                  -- NULL for creation entry
    to_status      VARCHAR(20) NOT NULL,
    reason         TEXT,
    actor_id       UUID        NOT NULL,
    correlation_id VARCHAR(255),
    occurred_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- APPEND-ONLY: No UPDATE or DELETE permitted on this table.
-- Enforced at repository layer (WalletStatusHistoryRepository only exposes append()).

ALTER TABLE wallet.wallet_status_history
    ADD CONSTRAINT wallet_status_history_wallet_id_fk
    FOREIGN KEY (wallet_id) REFERENCES wallet.wallets(id);

-- Chronological pagination
CREATE INDEX wallet_status_history_wallet_id_occurred_at_idx
    ON wallet.wallet_status_history (wallet_id, occurred_at ASC);
```

### Field Notes

| Field | Notes |
|---|---|
| `from_status` | NULL for the initial creation entry (status = `pending`) |
| `reason` | Required for privileged transitions (freeze, unfreeze, close, suspend, restrict) |
| Immutability | Repository layer only exposes `append()`; no `update()` or `delete()` |

## Balance Architecture (Derived, Never Stored)

```
available_balance = max(0, ledger_balance − held_amount)

where:
  ledger_balance = LedgerModuleContract::getBalance(currency_pockets.ledger_account_reference)
  held_amount    = SUM(wallet_holds.amount) WHERE pocket_id = ? AND status = 'active'
```

No `current_balance`, `available_balance`, or `ledger_balance` column exists on `currency_pockets`. Any column holding a directly-mutated balance would violate constitution Principle 4.

---

## Concurrency Invariant

Before every debit or hold placement:

```sql
BEGIN;
SELECT * FROM wallet.currency_pockets WHERE id = :pocket_id FOR UPDATE;
-- compute available_balance within transaction
-- if sufficient: INSERT INTO wallet.wallet_holds ...
-- else: ROLLBACK
COMMIT;
```

The `FOR UPDATE` on `currency_pockets` serializes concurrent debits at the row level. Two concurrent debits against the same pocket are guaranteed to execute sequentially.

---

## State Machine: wallet.wallets.status

```
pending → active
active  → frozen | suspended | restricted | closed
frozen  → active | closed
suspended → active | closed
restricted → active | closed
closed  → (terminal; no outbound transitions)
```

Invalid transitions return HTTP 422 `INVALID_WALLET_TRANSITION`.
Every transition produces one `wallet_status_history` row.

---

## State Machine: wallet.currency_pockets.status

```
active → disabled
disabled → active (re-enable; admin only)
```

All pockets transition to `disabled` on wallet closure.

---

## State Machine: wallet.wallet_holds.status

```
active → released  (transaction settled or cancelled)
active → expired   (wallet:expire-holds job)
```

`released` and `expired` are terminal hold states.
