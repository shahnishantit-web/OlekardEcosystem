# Data Model: Unified Design System

**Feature**: E35 Unified Design System
**Date**: 2026-10-10

---

## Overview

This feature has no database entities. The "data model" for a design system is the token schema: the structure, naming conventions, and relationships between token tiers.

---

## Token Schema

### Tier 1: Primitive Tokens

Raw named values. Platform-agnostic. Defined in `packages/design-system/tokens/color.json` (and sibling files for spacing, typography, etc.).

```
PrimitiveToken
├── name: string          (e.g., "color.green.600")
├── value: string         (e.g., "#16A34A")
├── type: "color" | "dimension" | "number" | "string" | "fontFamily" | "duration" | "cubicBezier"
└── group: string         (e.g., "green", "blue", "teal", "neutral", "brand")
```

**Color primitive groups** (to be defined/updated in `color.json`):
- `color.green.*` — Consumer palette (100–950 scale + named: `primary`, `dark`, `light`, `surface`, `background`, `accent`)
- `color.blue.*` — Agent palette
- `color.teal.*` — Admin palette
- `color.orange.*` — Merchant palette
- `color.purple.*` — Connect palette
- `color.gold.*` — ODSA palette
- `color.brand.*` — OleKard master brand (navy, midnight, gold, goldLight)
- `color.neutral.*` — Shared neutrals (white, secondary, border, and 0–950 scale)
- `color.status.*` — Shared semantic status (success, warning, error, info — both fg and bg variants)

---

### Tier 2: Semantic Tokens

Role-based mappings to primitive tokens. Defined per application theme. These are the tokens that application code MUST reference.

```
SemanticToken
├── name: string          (e.g., "theme.admin.background")
├── value: reference      (e.g., "{color.teal.background}")
├── type: inherited from primitive
└── theme: "consumer" | "agent" | "admin" | "merchant" | "connect" | "odsa" | "shared"
```

**Required semantic slots per application theme**:

| Slot | Purpose | Consumer | Agent | Admin |
|------|---------|----------|-------|-------|
| `background` | App background | `color.green.background` (#001B12) | `color.blue.background` (#001329) | `color.teal.background` (#001A1D) |
| `surface` | Card/panel background | `color.green.surface` (#062A1A) | `color.blue.surface` (#061B3A) | `color.teal.surface` (#062A2A) |
| `primary` | Brand primary color | `color.green.primary` (#16A34A) | `color.blue.primary` (#2563EB) | `color.teal.primary` (#0F766E) |
| `primaryDark` | Primary pressed/hover | `color.green.dark` (#15803D) | `color.blue.dark` (#1D4ED8) | `color.teal.dark` (#115E59) |
| `primaryLight` | Primary subtle | `color.green.light` (#4ADE80) | `color.blue.light` (#60A5FA) | `color.teal.light` (#2DD4BF) |
| `accent` | Secondary highlight | `color.green.accent` (#84CC16) | `color.blue.accent` (#38BDF8) | `color.teal.accent` (#14B8A6) |
| `foreground` | Primary text | `color.neutral.white` (#FFFFFF) | same | same |
| `mutedForeground` | Secondary text | `color.neutral.secondary` (#B8C4D0) | same | same |
| `border` | Dividers / outlines | `color.neutral.border` (#294052) | same | same |
| `success` | Success state | `color.status.success` (#22C55E) | same | same |
| `warning` | Warning state | `color.status.warning` (#F59E0B) | same | same |
| `error` | Error / destructive | `color.status.error` (#EF4444) | same | same |
| `info` | Informational | `color.status.info` (#38BDF8) | same | same |

---

### Tier 3: Component Tokens

Scoped to a specific component type. Reference semantic tokens. Defined alongside component implementations, not in the shared token source.

```
ComponentToken
├── name: string          (e.g., "button.primary.background")
├── value: reference      (e.g., "{theme.primary}")
├── component: string     (e.g., "button", "badge", "card", "table")
└── state: "default" | "hover" | "pressed" | "focused" | "disabled"
```

## Platform Output Files

Style Dictionary generates platform-specific output from the JSON sources:

### Web Output: CSS Custom Properties

**File**: `packages/design-system/build/css/tokens.css`

```css
:root {
  /* Primitive colors */
  --color-green-primary: #16A34A;
  --color-blue-primary: #2563EB;
  --color-teal-primary: #0F766E;
  /* ... all primitives */
}

/* Per-application theme overrides */
[data-theme="admin"], .theme-admin {
  --ok-primary: var(--color-teal-primary);
  --ok-background: var(--color-teal-background);
  --ok-surface: var(--color-teal-surface);
  /* ... all semantic slots */
}
```

The admin app applies `data-theme="admin"` to its root element (or relies on the default `:root` block for admin since it is the only current web app).

## Application Theme Factories (Flutter)

Each Flutter app defines a theme factory that builds `ThemeData` + `OkThemeExtension` from the shared `OkTokens` constants:

### Consumer App: `apps/customer/lib/core/theme/app_theme.dart`

```dart
// Imports OkTokens from packages/design-system
ThemeData buildConsumerTheme() => ThemeData(
  useMaterial3: true,
  colorScheme: ColorScheme.dark(
    primary: OkTokens.colorGreenPrimary,
    surface: OkTokens.colorGreenSurface,
    error: OkTokens.colorStatusError,
    // ...
  ),
  extensions: [OkThemeExtension.consumer()],
);
```

### Agent App: `apps/agent/lib/core/theme/app_theme.dart`

```dart
ThemeData buildAgentTheme() => ThemeData(
  useMaterial3: true,
  colorScheme: ColorScheme.dark(
    primary: OkTokens.colorBluePrimary,
    surface: OkTokens.colorBlueSurface,
    // ...
  ),
  extensions: [OkThemeExtension.agent()],
);
```

```dart
class OkThemeExtension extends ThemeExtension<OkThemeExtension> {
  final Color primary;
  final Color primaryDark;
  final Color primaryLight;
  final Color background;
  final Color surface;
  final Color accent;
  final Color navActiveColor;
  final Color successBg;
  final Color warningBg;
  final Color errorBg;
  final Color infoBg;

  const OkThemeExtension({
    required this.primary,
    required this.primaryDark,
    required this.primaryLight,
    required this.background,
    required this.surface,
    required this.accent,
    required this.navActiveColor,
    required this.successBg,
    required this.warningBg,
    required this.errorBg,
    required this.infoBg,

  factory OkThemeExtension.consumer() => OkThemeExtension(
    primary: OkTokens.colorGreenPrimary,
    primaryDark: OkTokens.colorGreenDark,
    primaryLight: OkTokens.colorGreenLight,
    background: OkTokens.colorGreenBackground,
    surface: OkTokens.colorGreenSurface,
    accent: OkTokens.colorGreenAccent,

    successBg: OkTokens.colorStatusSuccessBg,
    warningBg: OkTokens.colorStatusWarningBg,
    errorBg: OkTokens.colorStatusErrorBg,
    infoBg: OkTokens.colorStatusInfoBg,
  );

  factory OkThemeExtension.agent() => OkThemeExtension(
    primary: OkTokens.colorBluePrimary,
    // ... Agent Blue values
  );

  @override
  OkThemeExtension copyWith({...}) => ...;

  @override
  OkThemeExtension lerp(OkThemeExtension? other, double t) => ...;
}
```

## Style Dictionary Config Extension

**File**: `packages/design-system/style-dictionary.config.js`

Extend to generate per-application theme files:

```javascript
module.exports = {
  source: ['tokens/**/*.json'],
  platforms: {
    css: {
      transformGroup: 'css',
      buildPath: 'build/css/',
      files: [
        { destination: 'tokens.css', format: 'css/variables' },
        { destination: 'themes/admin.css', format: 'css/variables', filter: token => token.attributes.theme === 'admin' },
        { destination: 'themes/consumer.css', format: 'css/variables', filter: token => token.attributes.theme === 'consumer' },
      ],
    },
    dart: {
      transformGroup: 'flutter',
      buildPath: 'build/dart/',
      files: [{ destination: 'tokens.dart', format: 'flutter/class.dart' }],
    },
  },
};
```

## Validation Rules

- Every semantic token MUST reference a valid primitive token (no raw hex in semantic tier).
- Every component token MUST reference a valid semantic token (no raw hex in component tier).
- The Style Dictionary build MUST complete with 0 errors and 0 unresolved references.
- The generated `tokens.dart` MUST parse without Dart analysis errors.
- The generated `tokens.css` MUST be valid CSS.
