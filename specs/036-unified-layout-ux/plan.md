# Implementation Plan: Unified Application Layout & UX Architecture

**Branch**: `036-unified-layout-ux` | **Date**: 2026-10-10 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/036-unified-layout-ux/spec.md`

---

## Summary

E36 modernizes the application layout and navigation architecture across the three primary OleKard applications — Admin Portal (Next.js), Customer Mobile App (Flutter), and Agent Mobile App (Flutter) — by implementing production-ready navigation shells, dashboards, and page templates built on top of the E35 Unified Design System tokens. No business logic, API contracts, authentication rules, or database schemas are changed.

Technical approach:
- **Admin**: Create `app/(admin)/layout.tsx` (Next.js nested layout) wrapping all 54 admin routes with `AdminShell` → `AdminSidebar` + `AdminHeader`. Reuse existing `NAV_SECTIONS` for navigation. Build 6-card KPI dashboard.
- **Customer**: Update `MainShell` from 4 to 5 tabs, apply Consumer Green theming, add `WalletSummaryCard`.
- **Agent**: Extract `ScaffoldWithBottomNav` to `agent_shell.dart`, update to 5 tabs, build `FloatStatusCard` + `AgentDashboardHeader` + `TransactionStepFlow`.
- **Shared**: Migrate 7 duplicated Flutter widgets to `packages/design-system/lib/src/widgets/`.

---

## Technical Context

**Language/Version**: TypeScript 5.x (Admin Next.js), Dart 3.3+ / Flutter (Customer + Agent)

**Primary Dependencies**:
- Admin: Next.js 14+ App Router, Tailwind CSS (E35 tokens), React 18
- Flutter: flutter_riverpod ^2.5.1, go_router ^13.2.0, design_system (local package path)
- No new packages introduced (spec assumption 6)

**Storage**: `sessionStorage` (admin sidebar collapse state only) — no new DB or file storage

**Testing**:
- Admin: Jest + React Testing Library (existing setup)
- Flutter: flutter_test, golden tests (existing setup)

**Target Platform**: Web (Admin, Chrome/Firefox/Safari), iOS 15+ / Android 8.0+ (Flutter apps)

**Performance Goals**: Sidebar collapse animation ≤200ms (SC-006); KPI dashboard 6 parallel API calls on mount

**Constraints**:
- No new npm packages (Admin)
- No new Flutter pub packages
- E35 tokens must not be modified (`tokens.css` is hand-maintained — NEVER run `npm run tokens:build`)
- E01 authentication contracts must be preserved
- All colors via `OkTokens` / `OkThemeExtension` / CSS custom properties — no hardcoded hex

**Scale/Scope**: 54 admin routes, 34 customer routes (2 new), 30 agent routes (1 moved to shell), 7 widgets migrated to shared package

## Implementation Strategy

**MVP (Phase 3 only — US1 Admin Shell)**:
The admin shell alone (with sidebar, header, breadcrumbs) delivers the highest user-visible improvement — transforming the fragmented 54-page portal into a cohesive navigation experience. If time-constrained, deliver Phase 3 first and validate with SC-002.

**Full delivery order** (optimized for independence):
1. Phase 1+2 (setup + shared widgets) — enables all downstream work
2. Phase 3 (admin shell) + Phase 6 (customer shell) + Phase 8 (agent shell) — run in parallel
3. Phase 4 (admin dashboard) + Phase 7 (customer polish) + Phase 9 (agent polish) — run in parallel
4. Phase 5 (admin page templates) — after admin shell is stable
5. Phase 10+11 (validation + polish) — final gate
