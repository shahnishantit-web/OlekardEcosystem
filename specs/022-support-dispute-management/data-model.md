## State Machines

### SupportTicket Status Machine

```
open ──────────────────────────► in_progress
  │                                   │
  │                                   ▼
  │                               resolved
  │                               │     │
  │                               │     ▼
  │                               │   closed
  │                               │
  │◄──────────────────────────────┘  (reopen from resolved)
open ◄─────────────────────────────── closed  (reopen from closed)
```

Allowed transitions:
- `open` → `in_progress` (assign)
- `in_progress` → `resolved` (resolve, requires resolution_note)
- `resolved` → `closed` (close, requires resolution_note)
- `resolved` → `open` (reopen by reporter or support manager)
- `closed` → `open` (reopen by support manager only)

---

### Dispute Status Machine

```
raised ──────────────► evidence_submitted ──────────────►
  │                                                      │
  │◄────────────────────────────────────────────────────►│
  │                                                      │
  └──────────────────► under_investigation ◄─────────────┘
                              │
             ┌────────────────┴────────────────┐
             ▼                                 ▼
         approved                           rejected
      (pending_confirmation
       if maker-checker on)
             │
             ▼
          refunded
```

Escalation is a flag (not a status change); `escalated = true` can be set from `raised`, `evidence_submitted`, or `under_investigation`.

All models use `$connection = 'platform'` with schema-qualified table names (e.g. `support.support_tickets`). This follows the established codebase pattern (Fees, Commission, Transfer modules) where models participating in `DB::connection('platform')->transaction()` alongside the outbox publisher must use the same connection for true atomicity. Migrations still use `Schema::connection('support')` for schema-scoped DDL operations.

## Ledger Account References for E22

| Account Reference | Type | Normal Balance | Usage |
|---|---|---|---|
| `liability:disputes:{currency}` | `liability` | Credit | Platform dispute reserve; debited on refund |
| `asset:wallet:{reporterId}:{currency}` | `asset` | Debit | Reporter's wallet pocket; credited on refund |

The `liability:disputes:{currency}` account is registered once per currency (idempotent) by the `DisputeRefundService` before first posting. `ownerType = 'system_suspense'`.
